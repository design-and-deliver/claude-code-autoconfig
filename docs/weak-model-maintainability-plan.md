# Weak-Model Maintainability Plan

**Goal:** make claude-code-autoconfig safe for less-capable models to maintain — remove the lies
they would trust, make wrong edits fail loudly before they ship, then shrink the god files.

**Source audits** (full detail, evidence, and the greps cited below):
`docs/audit/00-prioritized-report.md` (synthesis), `01-where-the-repo-lies.md`,
`02-silent-failures.md`, `03-hazards-and-god-files.md`. Finding IDs below (e.g. 01-B7, 02-4.1,
T3, C2) refer to those files.

**How to execute this plan**

- **One substep per fresh session**, in order, top to bottom. Each substep is self-contained:
  read only this doc's header (traps + rails), the substep, and the audit findings it cites.
- Every substep ends with a **Verify** step (real commands) and a **commit**. Do not start the
  next substep in the same session.
- **After Verify + commit: append a Ledger entry** (bottom of this doc), check the substep's
  box, then prompt the user to `/clear` and then `/continue` — /continue is plan-aware: it
  detects the plan-substep session, reads the Ledger, verifies the last commit hash, and starts
  the next unchecked substep.
- This repo is a **published npm package with real users**. Nothing in this plan is deployed:
  per `.claude/rules/deploy-approval.md`, never run `npm version`/`npm publish` without the
  user explicitly saying so.

## ⛔ Standing trap warnings — read before ANY substep

From audit 03 (full inventory: `docs/audit/03-hazards-and-god-files.md`). An innocent-looking
edit that violates one of these runs clean and breaks at runtime:

1. **Additive-only serialized state (T16, T3).** Never rename/repurpose a field in any file that
   lives in user projects: `.claude/.autoconfig-plugins.json`, `.autoconfig-whats-new.json`
   (segment `kind` enum included), `cca.config.json`, `.claude/hooks/.titles/*.history.jsonl`
   (`ts`/`title`/`tokens` + the `' — '` title separator), `.token-guard/*`. Add optional fields
   with defaults instead.
2. **`DEV_ONLY_FILES` (bin/cli.js:751) is the install gate (T1)** — not package.json `files`.
   It must stay a one-line, single-quoted array literal named exactly `DEV_ONLY_FILES`: three
   tests parse cli.js **source** with `/const DEV_ONLY_FILES = \[([^\]]+)\]/`. Reformatting it
   silently empties the parsed list.
3. **Generated files (T7, G4).** Never hand-edit `CHANGELOG.md` (rebuilt from git history on
   `npm version`; reword via `Changelog:` commit trailers or the OVERRIDES map) or
   `.claude/docs/autoconfig.docs.html` (rebuilt by `node .claude/scripts/sync-docs.js`, which
   splices at exact string markers — reformatting the HTML breaks the next sync).
4. **`bin/cli.js` has no `main()` (G1).** Install correctness is top-level statement order:
   `previousVersion` read before copy; `isUpgrade` detection before copy; command snapshot
   before `copyDir`; what's-new write before the `--bootstrap` early-exit; pin gate before any
   copy. Never reorder top-level statements without re-verifying these. Never extract the ANSI
   boxes or `DEV_ONLY_FILES` out of cli.js — tests regex its source (T14: the box test finds
   boxes by regexing `console.log('…╔…')` literals).
5. **terminal-title.js: single file, canonical here (G3, T8).** Never split it into modules;
   never edit any copy except `.claude/hooks/terminal-title.js`, and after editing run
   `node scripts/sync-terminal-title.js --write` then `npm test`. The parity test **skips on
   CI** — CI green ≠ fleet in sync.
6. **Machine-read strings that look like prose (T2, T5, T12, T15, C5).** Never reword: the
   `AUTO-GENERATED BY /autoconfig` marker (frozen forever — old installs' CLAUDE.md can't be
   updated); the `<!-- @applied -->` block in autoconfig-update.md (cli.js:976 matches only the
   byte-exact empty block); token-guard `--analyze` digest headers + "live context at end";
   the `name|event` glyph-file format; quoted protocol phrases in command files that
   `test/cli-install.test.js` greps (cca-block markers, flag paths, config keys).
7. **Hook `command` strings in settings.json are identity (T4).** `mergeSettingsInto` dedups by
   exact command string — rewording a shipped hook command makes every upgrade ADD a duplicate
   entry (hook runs twice). Never dedupe the two Notification entries (`--idle-rescue` selects
   a distinct code path); never drop `CLAUDE_CODE_DISABLE_TERMINAL_TITLE: "1"`.
8. **Forget-and-rot lists (T1, T11, C6, C7).** New dev-only file → `DEV_ONLY_FILES`. New
   shipped top-level `.claude/` entry → `AUTOCONFIG_FILES` (bin/cli.js:50). New cca-owned hook →
   `MANAGED_HOOKS` (bin/cli.js:880). New `test/*.test.js` → the `npm test` chain in
   package.json (nothing auto-discovers it).
9. **Command-file edits need `<!-- @version N -->` bumps (T6)** — an unbumped edit still ships
   but is silently dropped from users' upgrade reports.
10. **Changelog discipline (C1).** Commit subjects keep their `feat:`/`fix:` prefix; user-facing
    wording goes in a `Changelog:` body trailer; commits about dev-gated or internal work carry
    `Changelog: none` — otherwise the bullet appears verbatim on users' upgrade screens for a
    feature they can't receive.
11. **Hooks fail silent by design.** token-guard, terminal-title, and the other hooks swallow
    errors and exit 0. "It didn't error" proves nothing — only the test suites see regressions.
    `npm test` runs everything, including the hook suites; run it before every commit.
12. **`test/golden-endings.json` and `.claude/updates/` numbering are append-only (T9, T5).**
    Never relabel/delete a golden-endings entry; never reuse an update number (next free: 005;
    002 is a tombstone).

**Global safety rails for every substep**

- Where docs and code disagree, **fix the docs to match the code** — never "correct" working
  code to match a stale doc.
- Before deleting anything the audit called dead, **re-run the recorded dead-grep yourself**
  (each deletion substep lists it). The audit's word alone is not enough.
- Deleting or renaming a file that a doc/rule references → update that doc **in the same
  substep**.
- Run `npm test` before every commit (it's the full suite). All substeps assume it starts green.
